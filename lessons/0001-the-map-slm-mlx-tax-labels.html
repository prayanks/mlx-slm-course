The map: SLM + MLX + tax labels

One idea, tightly scoped: you are not pretraining a model from scratch — you are specializing a small open instruct model on Apple silicon with MLX, using transaction→label demos as the project.

Today’s win

Correctly name the build path (base SLM → LoRA on labeled demos → eval as a classifier), place MLX in the stack, and reject the three most common wrong turns before you install anything.

01 Why this matters for your mission

You want deep fluency with small language models on a Mac via MLX. Indian transaction text → tax-ish labels (shopping, interest, dividends, …) is the project that forces real skills: messy SMS, a fixed label set, data format, LoRA, and metrics.

Without a map, people waste weeks on the wrong mountain: “train GPT from zero,” “build a 7B full fine-tune on a 16 GB laptop,” or “only prompt ChatGPT forever and never learn the stack.” This lesson is the compass. Hardware work starts next lesson — on your Mac, not this Linux host.

02 Three words, disambiguated

Small language model (SLM)

An SLM is a transformer language model with a modest parameter count — often hundreds of millions to a few billion — chosen so it runs and trains locally. It still does next-token prediction. “Small” is about deployability and iteration speed, not a different species of intelligence.

For this course, default bases live in the MLX Community — on your locked lab machine (M2 Pro · 32 GB), we standardise on ~0.5B–3B instruct models (often already 4-bit). A 7B QLoRA is optional later, not the first lab.

MLX

MLX is Apple’s open array framework for machine learning on Apple silicon. It uses Metal and unified memory (CPU and GPU share one pool — you don’t manually cuda:0 shuttle tensors the way you do on NVIDIA stacks). Install constraints from the docs: Apple silicon, macOS ≥ 14, native Python ≥ 3.10.

MLX LM

mlx-lm is the package built on MLX for running and fine-tuning LLMs/SLMs: generate text, convert/quantize, LoRA/QLoRA/full fine-tune, fuse adapters. Primary command you will live in: mlx_lm.lora — documented in the official LoRA guide.

Stack in one line

MLX = tensor engine on Apple silicon · mlx-lm = LLM/SLM tools on that engine · your project = LoRA so a small instruct model emits tax labels from transaction text.

04 Classification as language modeling

A classical ML classifier maps text → a discrete class index with a softmax head. An SLM maps text → tokens. For this course we still get labels by making the desired tokens be the label: 

User: Classify this Indian bank transaction for personal books.
Text: UPI-AMZN_Pay-1234@okhdfcbank Rs.1,249.00
Assistant: shopping

That is supervised fine-tuning (SFT): the model imitates labeled input→output demos. We teach SFT inside this course from first principles — no other curriculum assumed. Here the “answer” is a short controlled string from a fixed vocabulary of labels, not an essay. At train time, mlx-lm expects JSONL in chat, completions, or text form (Data section of LORA.md). We will prefer formats where you can --mask-prompt so loss focuses on the label tokens.

Honest alternative (later)

For pure multi-class tagging, a small encoder + linear head (or even strong rules + merchant maps) can beat a generative SLM on latency and calibration. We still take the generative SLM path first because your mission is to learn SLMs and MLX. We will compare later so you know when the SLM is overkill.

05 The project shape: labels, not tax law

Income-tax “SFT” (Specified Financial Transactions under reporting rules) is a government reporting table of high-value events. That is not our label set.

Our course schema is a personal books / ITR-prep style taxonomy we will lock in a later lesson, starting roughly like:

  • shopping — goods/services spend (Amazon, swiggy, …)
  • interest_income — savings/FD interest credits
  • dividend — equity/mutual fund dividend credits
  • salary — employer credits
  • transfer — self/family UPI, own-account moves
  • tax_payment — challan / advance tax / TDS-related
  • investment — MF/SIP/stock purchase debits
  • other — residual (force the model to admit uncertainty)

Exact list will live in a reference sheet. Treat it as engineering schema, not legal advice.

06 What “done” looks like for the full course

  1. M2 Pro (32 GB) has mlx-lm; you can generate from a small instruct model offline.
  2. You can explain SFT as “imitate these demos” and write clean label demos yourself.
  3. You own a labeled JSONL (train/valid/test) of redacted transaction lines.
  4. mlx_lm.lora produces an adapter that improves held-out label accuracy.
  5. You can explain LoRA vs full FT, 4-bit QLoRA, fuse, and failure modes (label drift, leakage, format freestyle).
  6. You can say when you’d drop the SLM for rules or a classical classifier.
